# 2026-11-19 SBI unified professional UI and private work planner

Source baseline: feature/sbi-aws-control-tower-in-app-tab-20261119 @
3a72b71afab1ece158db67400b7aacccf65a0b2b.

Scope:
- Unified professional navy / teal styling on login, dashboard and original
  engineering Control Tower, preserving original Login v1.5 Firebase auth flow.
- In-page Control Tower tab remains a button and authenticated same-origin iframe.
- Removed "Backend API Reports" and the automatic Supervisor API Monitoring
  generated by dashboard.js. Old dashboard management form retains blocked
  financial imports; no financial API has been connected.
- Preserve Control Tower source-backed Project Priorities & Release Monitor,
  P0 Essential, Critical Obstructions, Staging History and Pending Task Pipeline.
- Replace obsolete *visible* owner task editor (previously relied on a
  separate disconnected SQLite + public GitHub publishing flow) with private
  "Owner-added priority tasks" and "Project notes" UI. The legacy DOM
  stays hidden only to avoid disrupting old source-only scripts.
- New Firebase session-guarded nonfinancial workspace API supports notes/tasks,
  edit/mark done/delete, due date, priority, account-scoped records and
  same-origin CSRF for mutations. Max 300 items and bounded text sizes.
- Data stored at /var/lib/sbi-control-tower-workspace/workspace.sqlite3 on AWS,
  mapped inside candidate to /data/workspace.sqlite3, UID 10001 owner.
  This persistent host volume is independent of finance, GitHub and public assets.
- Fail closed (503) if the mount is unavailable. Do not silently switch to
  browser local storage or a finance database.
- Previous source/task evidence and status cannot be modified by personal tasks.
- Caddy's global X-Frame-Options DENY is removed only from the *candidate*
  because it would override the same-origin embedded child response;
  the upstream Flask endpoints continue DENY by default and SAMEORIGIN
  only for /control-tower?embedded=1.

Deploy new independent candidate (no old containers replaced):
  sudo bash staging/aws_login_v150/deploy_workspace_ui.sh stage FULL_SHA
After successful QA, approved baseline and review:
  sudo bash staging/aws_login_v150/deploy_workspace_ui.sh activate FULL_SHA
Manual rollback:
  sudo bash staging/aws_login_v150/deploy_workspace_ui.sh rollback FULL_SHA

The existing /pipeline Basic Auth preview, old Firebase login and Control
Tower containers remain. No financial reports, imports or settlement enabled.
Existing release gates, stage/source QA and database safety policies remain.
