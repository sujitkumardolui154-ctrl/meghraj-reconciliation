# SBI Payment Evidence Fixed Excel Upload — 2026-11-20

The owner requested enabling the previously disabled Excel upload under Database Update > Payment Reconciliation, requiring a fixed three-column spreadsheet header:
  A1: Description
  B1: SOL ID
  C1: Credit Amount

The workbook template (PAYMENT EVIDENCE sheet) is generated by the authenticated
GET /api/payment-evidence/template endpoint. XLSX only, <=8MiB. The original
PAYMNENT worksheet and columns A-L must not be edited; the user copies the
source values into the fixed template, including Column I Credit.

API:
- GET /api/payment-evidence/template -> downloadable styled XLSX with SOL text formatting.
- POST /api/payment-evidence/upload -> requires verified Firebase session,
  exact same-origin double-submit CSRF and multipart XLSX; validates ZIP size,
  fixed headers, rows, amounts, formulas, duplicate candidate rows.
- GET /api/payment-evidence/uploads -> owner-only latest 20 staged receipts.
- GET /api/payment-evidence/uploads/<receipt_id> -> owner-only revalidated
  read-only preview and original SHA256 verification.

File bytes staged on the NEW private host path
  /var/lib/sbi-payment-evidence-staging
only, with owner UID 10001 and mode 0700. Files 0600. SQLite manifest
receipts.sqlite3 remains separate from the existing private project notes DB
and from all financial databases. A receipt stores SHA256, source row totals,
valid/review row counts and status, not any approved allocation. Duplicated
upload of same hash per user returns 409.

Every preview is limited to 50 rows; 30,000 maximum Excel data rows.
Numeric SOL IDs are flagged because leading zero padding can be lost.
Nonpositive credits, duplicate source lines, formula cells and invalid values
are flagged for human review. No automatic fuzzy mapping, bank payment
allocation, ledger update, invoice merge, payment reconciliation or write-off
is performed.

Legacy Excel Upload v1.3 under Invoice Data remains disabled until its own
financial API approval. Run Payment Reconciliation stays disabled.

The AWS release must stage as separate SHA-pinned container with new
evidence volume. Existing Control Tower, original /pipeline, Firebase login,
personal task volume and all financial release blocks remain intact.
